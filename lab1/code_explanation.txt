1. THE BIG PICTURE: WHAT ARE WE DOING AND WHY?
================================================================================
In real companies (like an e-commerce shop in Kazakhstan), customer data 
collected from websites and apps is often "dirty":
- Some customers make typos in their email addresses.
- Some enter impossible ages (like 140 or -5).
- Some enter invalid national IDs (IIN) that are not 12 digits.
- Some customers leave critical fields blank.
- Some customers explicitly say "No" to marketing emails (consent revoked).

If a company blindly sends marketing emails to everyone, it will:
1. Waste money sending emails to broken addresses.
2. Break the law (Kazakhstan's Personal Data Protection Law and GDPR) by 
   messaging people who did not give consent.
3. Violate privacy rules by exposing full names to third parties.

Therefore, our job in this lab is to build an automated Python "filter" (a Data 
Governance Engine) that inspects every record, isolates legal issues, checks 
quality, and produces a clean executive report for management.

Control 2: Email Format Check (Regex Explained)
-----------------------------------------------
Code:
```python
EMAIL_REGEX = r"^[\w\.-]+@[\w\.-]+\.\w+$"

def validate_email(email_value):
    if pd.isna(email_value):
        return False
    return bool(re.match(EMAIL_REGEX, str(email_value).strip()))

invalid_email_format_mask = df["email"].notna() & (~df["email"].apply(validate_email))
```

What does `r"^[\w\.-]+@[\w\.-]+\.\w+$"` mean?
Let's break down each symbol:
- `^` : Start of the text string.
- `[` and `]` : A set of allowed characters.
  * `\w` means any letter, number, or underscore (a-z, A-Z, 0-9, _).
  * `\.` means a literal dot (period).
  * `-` means a hyphen.
- `+` : Means "one or more" of the characters in the bracket.
- `@` : The email MUST contain exactly an '@' symbol.
- `[\w\.-]+` : One or more characters for the domain name (like "kbtu" or "gmail").
- `\.` : A dot separating domain name and extension (like ".kz" or ".com").
- `\w+` : The ending letters (like "kz", "com", "org").
- `$` : End of the text string.

How it evaluates:
- "arman@kbtu.kz" -> MATCH (Valid)
- "elena.p@gmail.com" -> MATCH (Valid)
- "invalid-email-at-com" -> NO MATCH (No '@' symbol! Flagged as INVALID format)
- `np.nan` -> Handled as missing, not format failure.

Result: Invalid Email Format Count = 1 (John Doe).

Control 2: Kazakhstan IIN Check (12 Digits)
-----------------------------------------------
Code:
```python
IIN_REGEX = r"^\d{12}$"

def validate_iin(iin_value):
    if pd.isna(iin_value):
        return False
    return bool(re.match(IIN_REGEX, str(iin_value).strip()))

invalid_iin_mask = ~df["kz_iin"].apply(validate_iin)
```

Explanation:
- In Kazakhstan, every citizen's IIN must be strictly 12 digits.
- `^` : Start of string.
- `\d` : Any numeric digit (0 to 9).
- `{12}` : Exactly 12 digits in a row (no more, no less).
- `$` : End of string.
- In our data:
  * Customer 103 (John Doe) has `kz_iin` = "12345". That is only 5 digits!
  * All other 5 customers have 12-digit IIN strings.
- Result: Invalid KZ IIN Strings = 1.

Control 3: Name Anonymization (Pseudonymization)
-----------------------------------------------
Code:
```python
def anonymize_name(name: str) -> str:
    if not isinstance(name, str) or not name.strip():
        return ""
    parts = name.strip().split()
    if len(parts) == 1:
        return parts[0]
    first_initial = parts[0][0].upper()
    surname = " ".join(parts[1:])
    return f"{first_initial}. {surname}"

df["anonymized_name"] = df["full_name"].apply(anonymize_name)
```

Explanation:
- Under GDPR (Article 4) and Kazakhstan's PDP Law, "Pseudonymization" means 
  masking personal identifiers so data cannot be linked to a person without 
  extra keys.
- How the function works:
  1. `parts = name.strip().split()`: Splits `"Arman Aliyev"` by space into a 
     list: `["Arman", "Aliyev"]`.
  2. `first_initial = parts[0][0].upper()`: Takes the first letter of the first 
     name and makes it uppercase -> `"A"`.
  3. `surname = " ".join(parts[1:])`: Takes the rest of the name -> `"Aliyev"`.
  4. Returns `f"{first_initial}. {surname}"` -> `"A. Aliyev"`.
- Examples:
  * "Arman Aliyev"   -> "A. Aliyev"
  * "Elena Petrova"  -> "E. Petrova"
  * "John Doe"       -> "J. Doe"
  * "Aisha Saparova" -> "A. Saparova"
  * "Dmitry Ivanov"  -> "D. Ivanov"
  * "Sanzhar N"      -> "S. N"

6. LAB DEFENSE FAQ (CHEAT SHEET FOR YOUR INTERVIEW)
================================================================================

Q1: What is the RACI matrix and why can there be only ONE 'A' per row?
Answer:
RACI stands for Responsible, Accountable, Consulted, and Informed.
There must be exactly ONE 'A' (Accountable) per task because if two people are 
accountable, nobody takes responsibility when things go wrong ("if everyone is 
responsible, no one is"). Exactly one person must have final decision power.

Q2: What is the difference between a Data Owner and a Data Steward?
Answer:
- The Data Owner is a senior business executive (like a Director). They are 
  ACCOUNTABLE. They set policies, approve budgets, and decide the business rules 
  (e.g., "The record with the verified IIN wins").
- The Data Steward is the operational custodian. They are RESPONSIBLE. They 
  investigate the data day-to-day, find the duplicate records, match IINs, and 
  work with Data Engineers to merge them into a single clean record.

Q3: What does Article 12 of Kazakhstan's Personal Data Protection Law say?
Answer:
Article 12 requires Data Localization. It says that personal data of 
Kazakhstani citizens must be physically collected and stored on servers located 
INSIDE the Republic of Kazakhstan. Storing primary user databases directly in 
foreign cloud regions (like AWS in Frankfurt or Azure in the US) violates the 
law. Companies must use local data centers/clouds or a hybrid setup where 
primary data stays in Kazakhstan.

Q4: Why does our audit report show a Quality Score of 33.33%?
Answer:
Because out of 6 customer records audited, only 2 records (Customer 101 and 
Customer 102) passed all data quality validation rules (valid email, age within 
bounds, and valid 12-digit IIN). 2 divided by 6 is 0.3333, or 33.33%.

Q5: What is the difference between Anonymization and Pseudonymization?
Answer:
- Pseudonymization (what our `anonymize_name()` function does) masks names into 
  "A. Aliyev". The person can still be re-identified if someone has the lookup 
  key (like customer_id or IIN).
- True Anonymization irreversibly removes all identifying details so that the 
  person can NEVER be re-identified by anyone.
